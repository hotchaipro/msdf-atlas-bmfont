# msdf-atlas-bmfont

Converts a font atlas generated by [msdf-atlas-gen](https://github.com/Chlumsky/msdf-atlas-gen) into the [AngelCode BMFont](https://www.angelcode.com/products/bmfont/) format, so multi-channel signed distance field (MSDF) fonts can be used with engines and libraries that load BMFont `.fnt` files.

msdf-atlas-gen produces an atlas image plus a JSON layout describing each glyph. This tool reads that JSON and writes an equivalent BMFont descriptor that references the same atlas image.

## Features

- Writes BMFont descriptors in the **XML** format (default) or the **binary** format (version 3).
- Converts glyph positions, sizes, offsets and advances from msdf-atlas-gen's em-based metrics into BMFont's pixel-based metrics.
- Preserves the distance field parameters (atlas type and distance range), which renderers need to draw distance field glyphs but aren't included in a standard BMFont. See [Distance field extension](#distance-field-extension).

## Requirements

- [.NET 10 SDK](https://dotnet.microsoft.com/download) to build.
- msdf-atlas-gen to generate the atlas. A Windows build of msdf-atlas-gen 1.4 is included in [`external/`](external/); on macOS and Linux, build it from source.

## Building

```shell
dotnet build src/msdf-atlas-bmfont.csproj
```

To publish self-contained, single-file executables, which don't need .NET installed to run, for Windows (x64), macOS (Apple silicon and Intel) and Linux (x64):

```shell
dotnet publish src/msdf-atlas-bmfont.csproj -c Release
```

Each platform's executable is written to `artifacts/publish/<runtime identifier>/`, ready to attach to a release. To publish a single platform, including one not in that list such as `linux-arm64`, pass its [runtime identifier](https://learn.microsoft.com/dotnet/core/rid-catalog) with `-r`:

```shell
dotnet publish src/msdf-atlas-bmfont.csproj -c Release -r linux-arm64
```

The platforms published by default are listed in `PublishRuntimeIdentifiers` in [`src/msdf-atlas-bmfont.csproj`](src/msdf-atlas-bmfont.csproj).

## Usage

### 1. Generate the atlas with msdf-atlas-gen

Generate a PNG atlas and a JSON layout.

```powershell
msdf-atlas-gen.exe -font MyFont.ttf -type msdf -size 32 -pxrange 4 -format png
    -imageout MyFont.png -json MyFont.json
```

Any atlas type (`sdf`, `psdf`, `msdf` or `mtsdf`) can be converted, with either Y origin (`-yorigin top` or `bottom`) and either a symmetric (`-pxrange`) or an asymmetric (`-apxrange`) distance range. An asymmetric range spends the atlas's precision and padding on the side of the outline you need: for example, `-apxrange -6 2` reaches further outside the glyphs for outlines and glows, and `-apxrange -1 3` packs plain text into a smaller atlas. See the msdf-atlas-gen documentation for the full list of options.

### 2. Convert the JSON to BMFont

```
msdf-atlas-bmfont convert <input_path> -image:<atlas_image_path> [-format:xml|binary]
```

| Argument | Description |
|---|---|
| `<input_path>` | The JSON layout written by msdf-atlas-gen. |
| `<atlas_image_path>` | The atlas image file name to reference from the font. It is written into the font as-is, so it is normally a path relative to the `.fnt` file. Required. |
| `-format:xml|binary` | The output format. Defaults to `xml`. |

The output is written next to the input, with the same name and a `.fnt` extension.

```powershell
msdf-atlas-bmfont convert MyFont.json -image:MyFont.png
# Wrote MyFont.fnt

msdf-atlas-bmfont convert MyFont.json -image:MyFont.png -format:binary
```

The tool returns `0` on success, and prints usage and returns `-1` when the arguments are invalid.

## How values are converted

In this table, `size` is `atlas.size` (pixels per em), and y values are measured downward, as with `-yorigin top`. A `-yorigin bottom` atlas is flipped to match first.

| BMFont | Source in msdf-atlas-gen JSON |
|---|---|
| `info size` | `atlas.size` × `metrics.emSize` (the pixels per em of the unscaled font) |
| `common lineHeight` | `metrics.lineHeight` × size |
| `common base` | −`metrics.ascender` × size |
| `common scaleW`, `scaleH` | `atlas.width`, `atlas.height` |
| `char id` | `glyph.unicode` |
| `char x`, `y`, `width`, `height` | `glyph.atlasBounds`, shrunk inward to whole texels |
| `char xoffset` | `glyph.planeBounds.left` × size, plus the texels removed on the left |
| `char yoffset` | `common base` + `glyph.planeBounds.top` × size, plus the texels removed on the top |
| `char xadvance` | `glyph.advance` × size |

msdf-atlas-gen places each glyph's atlas bounds at the centers of its edge texels, so that bilinear filtering never blends in a neighboring glyph. The converter shrinks them to whole texels, which only trims padding outside the glyph's outline, and moves the glyph's offsets by the same amount, so the texels are drawn exactly where msdf-atlas-gen positioned them. Glyph offsets are measured from the rounded `base`, so every glyph sits exactly on the baseline.

Pixel values are rounded to the nearest integer (halves away from zero), because BMFont stores whole pixels. With msdf-atlas-gen's default `-pxalign`, glyphs are placed exactly vertically and within half a pixel horizontally. Rounding each `xadvance` introduces up to half a pixel of spacing error per character, which grows when text is drawn larger than the atlas size.

Whitespace glyphs have an empty rectangle. Every glyph is on page `0` and uses all channels (`chnl=15`).

### Limitations

- Kerning pairs are not converted.
- Only a single atlas image (page) is supported.
- The font face name is left empty.
- For multi-font atlases (`variants`), glyphs from all variants are combined and the metrics of the first are used.

## Rendering

[`sample/msdf.slang`](sample/msdf.slang) is a sample [Slang](https://shader-slang.org/) pixel shader for drawing the converted fonts with a sprite batch. Set its uniforms from the font file:

| Uniform | Value |
|---|---|
| `TextureSize` | `common scaleW`, `scaleH` |
| `PxRange` | `msdf distanceRange` |
| `DistanceOffset` | `msdf distanceRangeMiddle` + *embolden* |

*embolden* moves the glyph edges outward, in pixels of the font's native size (`info size`), which are also atlas texels: `0` draws the true outline, positive values make the glyphs bolder (as for an outline drawn behind the text) and negative values make them thinner. For example, `2` on a 36-pixel font moves the edges out by 2 pixels at that size, and scales along with the text. The edges can only move as far as the atlas encodes distances, so keep `DistanceOffset` well inside ±`PxRange` / 2.

Load the atlas image as a linear (not sRGB), uncompressed texture without premultiplied alpha or mipmaps, and sample it with bilinear filtering and clamp addressing. Color space conversion, compression or premultiplication change the stored distances and distort the glyphs. Single-channel atlases (`sdf`, `psdf`) must be expanded to RGB, as PNG loaders usually do, rather than loaded as a single-channel texture.

## Distance field extension

When the atlas type is a distance field type and the distance range is positive, the tool adds a section describing it. Readers that don't recognize it can ignore it.

**XML**

```xml
<msdf version="1" type="3" distanceRange="4" distanceRangeMiddle="0" />
```

**Binary**: an extra block with id `200`, little-endian:

| Size | Field | Value |
|---|---|---|
| 4 bytes | signature | `MSDF` |
| 1 byte | version | `1` |
| 1 byte | type | see below |
| 4 bytes | float | distance range, in atlas pixels |
| 4 bytes | float | distance range middle, in atlas pixels |

Later versions may append fields to the end of the block. A reader should check the signature and version, read the fields it knows, and skip the rest of the block using its size.

`type` is one of:

| Value | Type |
|---|---|
| `1` | `sdf` |
| `2` | `psdf` |
| `3` | `msdf` |
| `4` | `mtsdf` |

`distanceRange` is the width of the range of distances encoded in the atlas, in atlas pixels. `distanceRangeMiddle` is the signed distance encoded at the middle of that range, in atlas pixels, with positive distances inside the glyphs; it is zero for `-pxrange` and nonzero for an asymmetric `-apxrange`. A texel value *v* in [0, 1] encodes the distance (*v* − 0.5) × `distanceRange` + `distanceRangeMiddle`.
